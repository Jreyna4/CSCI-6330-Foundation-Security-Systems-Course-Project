# Response to the Milestone 1 feedback

Each point from the instructor's Milestone 1 feedback, what we changed, and where to find it.

| # | Feedback | What we changed | Where |
|---|---|---|---|
| 1 | Clarify the grouped split: why ~74.4% / 8.5% / 17% instead of 70 / 10 / 20? Give per-family supports and filenames. | Whole files move together, so fractions change in steps of ~1/N of the rows. With the pilot's 12 files (8.3% each), 2 test files = 17.0% and 1 validation file = 8.5% were the closest possible. Data prep now searches 2,000 seeded file assignments and keeps the one closest to the targets and to the overall family mix (every family in every split). With all 63 files the steps are ~1.6%. Every file, its split, and its raw and subset rows per family are written out. | `src/prepare_data.py` (`search_group_split`); `data/processed/split_files.csv`; `subset_summary.json` → `split.files`, `split.why_fractions_differ`, `family_counts_per_split`; README → Data, step 5 |
| 2 | Holding files apart does not guarantee capture/session independence. | Stated as a limitation. Each MERGED_CSV file contains (nearly) every attack type, so one capture can span several files; the release has no capture id, IPs or timestamps to group on. Added a nearest-neighbour diagnostic: distance from held-out rows to the nearest training row vs. between training rows. Exact cross-split duplicates are 0 by construction. | `split_files.csv` (`raw_families_present`); `data/processed/split_diagnostics.json`; README → Data, step 5 |
| 3 | Identify the exact 39 features and the transformation from the downloaded schema (official list has 46); justify the selection. | The MERGED_CSV release renames Duration (TTL) → `Time_To_Live`, adds `IGMP`, and omits 8 features (flow_duration, Srate, Drate, urg_count, Magnitue, Radius, Covariance, Weight): 46 − 8 + 1 = 39. Data prep checks the columns it reads against the official list on every run and writes the mapping, transform and training-pool statistics. No feature selection: all 39 are used, none is an identifier, and selecting on our data would add a leakage-prone tuning step. Transform: signed log1p, then standardization fit on the training pool. IAT sensitivity check planned. | `src/common.py` (`OFFICIAL_FEATURES`, `feature_schema`); `data/processed/feature_schema.csv`; README → Features |
| 4 | FedAvg is size-weighted, trimmed mean is not; add an unweighted-mean control. | New aggregation rule `mean` and two conditions (clean, attacked). Paired deltas now split the defense effect into "dropping size weighting" (FedAvg → mean) and "trimming" (mean → trimmed mean); the hypothesis table splits the H2 recovery the same way. | `src/run_federated.py` (`unweighted_mean`); `configs/mean_noniid*.yaml`; `src/summarize_results.py` (`PAIRS`, `hypothesis_check`) |
| 5 | Treat the three-attacker case as a stress test. | Relabeled everywhere. Runs with more attackers than values trimmed per side print `STRESS TEST` and record `stress_test: true`; the README and configs say that even ≤ 2 attackers carry no guarantee for label flipping. The sweep now runs after the paired comparison. | `src/run_federated.py`; `scripts/run_attacker_sweep.sh`; `configs/default.yaml`; README → Experimental conditions |
| 6 | Explain that assigning held-out rows by Dirichlet class proportions is label-informed benchmark construction, not a client-identification rule. | Stated in the code, the partition JSON (`label_informed_heldout_assignment: true`) and the README, with the conditions that make it acceptable: labels are never model inputs and the test set is never used for tuning. | `src/prepare_data.py`; `partitions/dirichlet_k10.json`; README → Data, step 7 |
| 7 | Define the multiclass PR-AUC summary and the treatment of classes with no support. | Per-family PR-AUC = one-vs-rest average precision; macro PR-AUC = unweighted mean over families with ≥ 1 positive and ≥ 1 negative. Macro F1 uses the same rule. | `src/common.py` (`compute_metrics`); README → Evaluation |
